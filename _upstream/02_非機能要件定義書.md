## 1. 非機能要件の体系

本ドキュメントは以下の 8 分野の NFR を定義する：

1. **性能（Performance）**: 起動、応答、スループット
2. **容量・スケーラビリティ**: ファイルサイズ、シンボル数、同時接続
3. **信頼性・可用性**: 稼働率、MTBF/MTTR、Crash 隔離
4. **セキュリティ**: 認証、権限、監査
5. **保守性・運用性**: ログ、監視、ドキュメント
6. **拡張性**: Plugin API、Capability
7. **互換性**: OS、アーキテクチャ、バージョン
8. **災害復旧**: Backup、Recovery、RTO/RPO

各 NFR は以下の形式で定義：
```
[NFR-XXX] 要件名
目標値：定量的な指標
前提：環境・条件
検証方法：how to verify
優先度：P0/P1/P2
```

## 2. 性能要件（Performance Requirements）

### 2.1 起動性能

#### [NFR-P-001] Kernel コールドスタートアップ時間
- **要件**: Kernel 初期化から TUI Ready までの時間
- **目標値**: ≤ 150 ms（参考開発機：Intel i7-12700, 32GB RAM, NVMe SSD）
- **前提条件**:
  - 索引・AI モデルは Lazy Load
  - Workspace は既にディスクに存在
  - ネットワーク遅延なし
- **測定方法**:
  ```bash
  time kernel .
  # "TUI Ready" 出力まで計測
  ```
- **検証方法**: Benchmark Suite で 5 回実行の中央値
- **優先度**: P0
- **根拠**: IDE 起動遅延は UX 致命的

#### [NFR-P-002] Plugin ホットロード時間
- **要件**: WASM Plugin の Load から Activation まで
- **目標値**: ≤ 500 ms（1 プラグイン）
- **検証方法**: 
  ```bash
  kernel plugin load <plugin-name> --measure
  ```
- **優先度**: P0

#### [NFR-P-003] ウォームアップ後起動
- **要件**: 再起動時（キャッシュ有効）
- **目標値**: ≤ 100 ms
- **優先度**: P0

---

### 2.2 リアルタイム応答性

#### [NFR-P-010] キー入力レスポンス
- **要件**: キー入力 → 画面更新の遅延
- **目標値**: P99 < 16 ms（ユーザー知覚 60fps に相当）
- **測定対象**: 通常テキスト入力・カーソル移動
- **前提条件**:
  - バックグラウンド AI/索引は非ブロック
  - 複数 Session は軽隔離
- **検証方法**:
  - Event Loop Profiling
  - Trace で`event_received` → `screen_update` を計測
- **優先度**: P0
- **禁止事項**: "AI 処理待ち" でブロック絶対禁止

#### [NFR-P-011] Command 実行のプリエンプション
- **要件**: INTERACTIVE タスク（キー入力）は BACKGROUND タスク（索引）を割り込み
- **測定**: Scheduler test で優先度逆転なし確認
- **優先度**: P0

#### [NFR-P-012] Cursor 移動応答
- **要件**: カーソルキー押下 → 画面反映
- **目標値**: < 5 ms
- **優先度**: P0

## 3. 容量・スケーラビリティ要件（Capacity & Scalability）

### 3.1 ファイルサイズ対応

- **要件**: Resident Memory が File Size に比例しない
- **目標**: 1GB ファイルで Resident Memory ≤ 100 MB
- **実装方式**: Lazy Read + Chunk Read + Memory Mapping
- **検証方法**:
  ```bash
  kernel edit 1gb-logfile.log
  # ps aux | grep kernel で RSS 確認
  ```
- **優先度**: P0

#### [NFR-C-002] 行数制限なし
- **要件**: Buffer の最大行数
- **目標**: ≥ 100 million lines（Streaming 処理前提）
- **実装**: Incremental Indexing

## 4. 信頼性・可用性要件（Reliability & Availability）

### 4.1 Crash 隔離

#### [NFR-R-001] Plugin Crash 隔離
- **要件**: Native Worker Plugin Crash が Kernel に波及しない
- **検証方法**: MVP 検証 5
  ```
  主動 Panic Plugin → Worker Crash
  確認事項:
    ✓ Kernel は alive
    ✓ Plugin 状態: FAILED
    ✓ Capability は removed
    ✓ 再起動可能
  ```
- **優先度**: P0
- **根拠**: Agent 実行の安全性

#### [NFR-R-002] WASM Plugin Crash 隔離
- **要件**: WASM Sandbox による隔離
- **検証方法**: WASM Plugin で panic → WebAssembly Runtime に trapped
- **優先度**: P0

#### [NFR-R-003] LSP Worker Crash
- **要件**: rust-analyzer 等のクラッシュ
- **復帰**: Kernel が自動検出・再起動
- **優先度**: P0

---

### 4.2 Worker Timeout 処理

#### [NFR-R-010] Worker Hang 検出
- **要件**: Worker が応答なし場合の検出・終了
- **タイムアウト**: 【TBD】秒
- **回復時間**: timeout 後 5 秒以内に Kernel 回復
- **検証方法**: Intentional hang test
- **優先度**: P0

#### [NFR-R-011] Command Cancellation
- **要件**: 実行中 Command の取消
- **目標**: < 1 秒で terminate
- **検証方法**: Cancellation test
- **優先度**: P0

---

### 4.3 Crash Recovery

#### [NFR-R-020] Kernel Crash 後の復帰
- **要件**: 未完了 Transaction の復帰
- **実装**: Journal-based Recovery
- **検証方法**: MVP 検証 5（Intentional Rollback）
  ```
  test.run 失敗 → transaction.rollback 呼び出し
  確認: Workspace が修正前状態に復帰
  ```
- **RTO**: ≤ 10 秒（crash 検出から復帰開始）
- **RPO**: 0（Journal の同期書き込み）
- **優先度**: P0

#### [NFR-R-021] OS Crash 時のデータ保全
- **要件**: OS Crash/Power Loss 時のデータ一貫性
- **実装**: Durable Event Log
- **検証方法**: Crash simulation（kill -9）
- **優先度**: P0

#### [NFR-R-022] Worker Crash Recovery
- **要件**: Worker Process 異常終了の検出・再起動
- **検証方法**: kill -9 worker process
- **優先度**: P0

---

### 4.4 稼働率

#### [NFR-R-030] Service Availability
- **要件**: 稼働率（Uptime）
- **目標**: ≥ 99.5%（ローカル開発環境）【TBD】
- **測定期間**: 1 ヶ月連続実行
- **優先度**: P1

#### [NFR-R-031] MTBF（Mean Time Between Failures）
- **要件**: 平均故障間隔

- **優先度**: P1

#### [NFR-R-032] MTTR（Mean Time To Recovery）

- **目標**: ≤ 10 秒
- **優先度**: P0

---

### 4.5 データ一貫性

#### [NFR-R-040] ACID Transaction セマンティクス

## 5. セキュリティ要件（Security Requirements）

### 5.1 認証・認可

#### [NFR-S-001] Session ベース権限管理
- **要件**: 各 Session が独立した Permission を持つ
- **Actor タイプ**: Human, LangGraph, AI Agent, CI, Plugin, Automation
- **Permission セット**: workspace.read, workspace.write, filesystem.read, filesystem.write, process.spawn, network, git, ai.local, ai.remote, secrets
- **実装**: Session object で Capability チェック
- **検証方法**: Permission test suite で各 Permission を検証
- **優先度**: P0

#### [NFR-S-002] Plugin Manifest による権限宣言
- **要件**: Plugin が必要な Permission を Manifest で明示
- **実装**: TOML Manifest の `[permissions]` セクション
- **デフォルト**: Deny（最小権限の原則）
- **検証方法**: Manifest parser test
- **優先度**: P0

#### [NFR-S-003] Runtime Permission チェック
- **要件**: すべての Command 実行時に Permission 検証
- **検証方法**: Permission denied test
  ```
  Reviewer Agent (workspace.write=false) が file.patch 実行
  → Permission denied error を返却
  ```
- **優先度**: P0

---

### 5.2 Workspace Security

#### [NFR-S-010] Path ベースアクセス制御
- **要件**: Session ごとに allowed_paths, read_only_paths, write_paths, blocked_paths 定義
- **実装**: File operation 前の path check
- **検証方法**: 
  ```
  Reviewer Agent allowed_paths = ["/src/auth"]
  → /src/auth.rs は read 可能
  → /src/git.rs は access 拒否
  ```
- **優先度**: P0

#### [NFR-S-011] Workspace Sandbox Enforcement
- **要件**: Session が Sandbox 外のファイルにアクセス不可
- **検証方法**: Sandbox escape test（symlink, hard link）
- **優先度**: P0

---

### 5.3 Process Security

#### [NFR-S-020] process.spawn デフォルト禁止
- **要件**: Permission なしで子プロセス起動不可
- **検証方法**: Unpermitted spawn fails
- **優先度**: P0

#### [NFR-S-021] Executable Allowlist
- **要件**: 実行可能な executable を whitelist で制御
- **例**:

- **優先度**: P0

#### [NFR-S-022] Environment Variable Filter
- **要件**: 子プロセスに渡す environment 変数を制限
- **デフォルト**: SSH_*, AWS_*, GITHUB_* などの Secret は除去
- **優先度**: P0

#### [NFR-S-023] Process Timeout
- **要件**: 子プロセスの最大実行時間制限
- **例**: test.run 最大 300 秒
- **優先度**: P0

### 5.4 Network Security

#### [NFR-S-030] Network Permission 段階化

- **検証方法**: Network access test for each level

#### [NFR-S-031] TLS 1.3 強制（HTTP）

## 9. 災害復旧要件（Disaster Recovery）

### 9.1 RTO/RPO

#### [NFR-D-001] RTO（Recovery Time Objective）
- **要件**: Kernel Crash からの復帰時間
- **目標**: ≤ 10 秒（Journal 復帰含む）
- **優先度**: P0

#### [NFR-D-002] RPO（Recovery Point Objective）
- **要件**: データ損失量
- **目標**: 0（Journal の同期書き込み）
- **優先度**: P0

### 9.2 バックアップ・復帰

#### [NFR-D-010] Workspace Backup
- **要件**: Workspace のバックアップ可能性
- **実装**: File snapshot（native FS 機能またはツール）
- **優先度**: P1

#### [NFR-D-011] Transaction Journal Backup
- **要件**: 未完了 Transaction の復帰
- **実装**: Local journal file
- **優先度**: P0
