# IDE1.0 IDE Shell — IPA 共通フレーム2013 標準ドキュメント体系

> **For Hermes:** 用户的调研需求 → "制定相关各级文档，符合日本IPA标准"
> **标准参照:** IPA 共通フレーム2013 (Software Engineering Center, 2013年3月4日発行)
> **V字モデル:** 左辺 (requirements / design) → 顶辺 (implementation) → 右辺 (verification / validation)

## Goal

按照日本IPA信息处理推进机构 (IPA/SEC) 发布的 **共通フレーム2013 (CF2013)** 标准, 为 IDE1.0 IDE Shell 项目制定完整 V字模型级别的各级文档, 涵盖プロセス・アクティビティ・タスク・注记 4层结构.

## Architecture

基于 V 字模型的文档层级:
- **左侧 (downstream):** PRD → SRS → SDD → STD
- **顶部 (development):** SUT (软件单元测试) → SIT (系统集成测试)  
- **右侧 (verification):** ATP → UAT → 验收
- **底部 (process):** QA计划 / 风险管理 / 配置管理 / 变更管理

## Tech Stack

- 文档格式: Markdown (与 CF2013 兼容 — CF2013 不规定文书形式)
- 编号系统: `[进程代号]-[アクティビティ]-[任务]-[序号]` (CF2013 §6 共通フレームの見方)
- 角色定义: 基于 CF2013 §7 プロセス体系 (Project/Technical/Software Implementation 三大类)
- 模板: 自定义 IPA 兼容模板 (保留 CF2013 4层结构)

## Tests / Validation

每份文档需要满足:
- 包含 IPA 4层结构 (プロセス → アクティビティ → タスク → 注記)
- 引用具体代码路径 (e.g. `crates/ide-shell-web/src/editor.html`)
- 包含 commit hash (指向具体实现)
- 中日英三语关键词
- 编号唯一 (DOC-NN format)

## Risks, Tradeoffs, and Open Questions

| Risk | Mitigation |
|---|---|
| 21 份文档可能过多 | 合并相关文档 (DOC-04 与 DOC-02 引用关系) |
| 用户希望中文文档 | 文档主体中文, 标题英文 (IPA 术语保留日文) |
| 项目仍在演进 (ulys-191-34) | 文档标注 "现状 2026-10-09" + 后续更新机制 |
| 测试矩阵 4 层 (UT/IT/ST/UAT) | DOC-08/09/10/11 分别记录 |
| CI 9 jobs | DOC-15 包含完整 CI workflow |
