# ide-fast Parity Implementation Plan (merged from 6 area audits)

Order within each batch is impact desc, effort asc. Each batch compiles and can be committed alone. Batches 1-2 hold the quick, high-value wins. The command registry comes in batch 3, so batches 1-2 use direct hooks into the existing `shortcuts()` and `menu()` code, which batch 3 then replaces.

## Architectural decisions to make first

| # | Decision | Recommendation | Blocks |
|---|---|---|---|
| A1 | **JS engine for script plugins** (PPA, doc-graph, pele/mermaid, the 6 theme-* mains are stubs) | rquickjs: it has memory limit, stack limit and a wall-clock interrupt handler, which match the 15s CALL_TIMEOUT. boa lacks a wall-clock interrupt. Benchmark loading the 730 KB pele bundle before committing. This contradicts the ROADMAP deferral, so confirm with the user. | Batch 8; plugin commands, PPA, doc-graph, mermaid |
| A2 | **Native fallback if A1 is rejected** | Native egui doc-graph view fed by md_struct. A native mermaid subset (flowchart, sequence, pie) with an "unsupported" hint. Do not port PPA to Rust, because that forks semantics. | Batch 8 alternative |
| A3 | **SVG rasterizer** (resvg/usvg via egui_extras `svg`, about 1-2 MB) | Needed only if A1 is accepted, for plugin SVG results and click-to-line. Weigh against the binary-size goal. | Batch 8 |
| A4 | **AI Chat panel** (XL, needs an HTTP client such as ureq, a consent flow, and API key storage in settings) | The ROADMAP says this stays in the Tauri version. Needs an explicit scope decision: parity per the user's request, or an exclusion. The tool loop can reuse `editcore::agent_api`. | Batch 8 (optional) |
| A5 | **Glass/translucent themes** (transparent viewport, DWM Mica/Acrylic) | The workspace forbids unsafe, so use `window-vibrancy` or an isolated crate. Needs a screen-capture crate for luminance sampling. XL effort for medium impact: do it last, or exclude it. | Batch 8 |
| A6 | **i18n (zh/ja/en)**: touches every literal string | Do it right after the menu rewrite, in batch 5. Doing it later means re-touching every string. Decide whether to port the ~600-key I18N table in full or only the menu/dialog keys. | Batch 5 |
| A7 | **Moving scm.rs git logic out of the Tauri crate** into editcore or a shared module (SCM panel, Git Diff) | Shared pure-std module. Needs sign-off since it touches the other front-end. | Batch 7 |
| A8 | **Vim mode, SQL*Plus** | Exclude (no editcore semantics). Record in the ROADMAP. | none |

## Batch 1: Safety, file lifecycle and the fastest editing wins

Mostly small items in `doc.rs` and `app.rs`; no new crates.

1. Large-file cap (default 4 MB, up to 32 MB) and NUL/binary refusal in `Doc::open`. Dropped `.zip` goes to plugin import and directories open as a folder.
2. External-change detection on window focus (`FileStamp`), plus File > Reload and a prefs checkbox.
3. Close-window confirmation for unsaved docs (`CancelClose`), plus the confirm-close pref.
4. Go to line (Ctrl+J/G modal).
5. Toggle line comment (Ctrl+/), using the comment token from `TypeConfig`.
6. Tab/Shift+Tab block indent (`transform_lines` as one undo step), plus a "Tab inserts spaces" setting.
7. Selection transforms: upper/lower, full/half width, kana, tab<->space, with a menu submenu and Ctrl+F6-F10.
8. Wire the existing `edit_cmd` commands to menu and keys: word-cut, word-delete, line-cut-to-end, cut-line, cut-line-start, delete-line-to/from, join-with-prev, select-word, add-line-above/below, copy-crlf/lines/passage/linenum, paste-box, column-delete/replace. Align the conflicting Ctrl+D, Ctrl+Shift+K and Alt+Shift+Up/Down bindings with Tauri.
9. Sort/trim/unique lines and global dedupe.
10. Double-click word, triple-click line, Ctrl+W, F6 anchor mode, paragraph select, cur-line-center.
11. Overwrite (Ins) mode with a status indicator.
12. Read-only mode flag.
13. Markdown edit commands (md-bold etc.) plus md-only shortcuts that shadow the Sakura keys.

## Batch 2: Search and Grep parity

1. Find bar rework: whole-word, wrap toggle, selection scope, seed the needle from the selection, incremental find-as-you-type, regex validation, Esc/Enter/Shift+Enter, Ctrl+R/Ctrl+G/Ctrl+F3.
2. Replace-one with `match_expand` ($1 \1 $&), and replace-all cursor/selection placement.
3. Highlight-all matches, cached per (doc, rev, needle, flags).
4. Grep dialog: separate folders/exclude/charset fields, whole-word/subfolders/outside/this-file, empty pattern means filename search, fallback root, output formats, jump with column and centring.
5. Grep as a streaming, cancellable job: per-subfolder shards, Esc to stop, 5000-hit cap.
6. Grep result document (Sakura header/footer, Enter/double-click jump, Ctrl+F inside results).
7. Grep-replace option parity and reload of open clean tabs.
8. Search defaults persisted in prefs.
**批次 2 状态 (已实现)**: 1-8 项均已落地 (find.rs / grep.rs)。查找、增量查找、强调、置换都走 editcore::search_ops (step / hits / match_expand / validate), 没有用 search_highlight / incremental_search (Tauri 两个前端也没用它们)。Ctrl+G 改为 Grep (同 Tauri), 转到行只留 Ctrl+J。未做: 迁移 / Migemo 增量查找 (isearch)、Grep 结果里命中词强调 (结果文档用查找栏的强调即可)、单个超大目录内的取消粒度 (分片最深两层, 更深的整棵一片)。
