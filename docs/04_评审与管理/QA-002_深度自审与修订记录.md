## 2. 审查覆盖与审查边界

- 静态编号：FR 49项、NFR 28项；UT 98项、IT 49项、ST 45项。仅证明编号和用例规划存在，**不保证每个场景的行为断言充分**。
- 高风险用例已补充确切数据/断言：宿主撤销、编码、模式切换、Slash、Mermaid、插件Manifest、Worker崩溃及越权。
- 此包没有任何编辑器生产代码，不可能开展真正的UT、IT、ST或代码覆盖率统计。
- Stage0未确定真正的宿主API与原子Undo可行性、UTF-8/UTF-16映射、IME行为、OS沙箱/IPC和预览实现。
- 测试数据都是离线静态样本，不能将插件Manifest误认为可执行插件。

## 3. 决策与发布建议

**结论：暂缓G1/G2设计冻结。** 文档可作为POC实施输入；须先完成 `G0_宿主可行性验证清单.md` 的阻断项，再逐条补全剩余测试用例的具体输入、操作、可观察结果与判定标准。没有实际证据时，Excel中所有执行结果维持“未执行”。

## 4. 自审方法

1. 对照文档FR/NFR编号和优先级，对照测试JSON及Excel。
2. 人工抽查BD/DD关键算法：单一权威Buffer、版本锁、Offset变换、文件保真、插件隔离、懒加载。
3. 检查测试中的样本类型与用例场景一致性并修正。
4. 对插件Schema执行验证，对样本编码和哈希结构执行静态检查。
5. 重新生成Excel相关条目，再执行ZIP CRC、SHA-256清单校验。

以上为文档与静态数据审查，不是已通过的系统测试。
