# SPA-01 — Sakura Editor 功能对标规格

本文是 IDE1.0 替代 Sakura Editor 的**验收契约**。目标不是"有个 grep 就算数"，而是
用户从 Sakura 迁移过来时，同一个操作、同一个快捷键、同一个边界行为，都得到等价或更好的结果。
唯一允许的实现差异：核心逻辑用 Rust 重写，不依赖 bregonig/bregexp 等 C++ 正则库与 COM 组件。

来源：`sakura-editor/sakura` 官方 help 文档（以 master 分支 help/ 为准）。
每条功能标注 Sakura 版本引入点，便于对齐行为。

## 3. 验收原则

1. **不留假实现**：任何标为"已支持"的规格必须可被 UAT 用例断言，不得靠"调用不报错"冒充。
2. **行为一致优先于实现差异**：用户从 Sakura 迁移，快捷键和边界行为必须一致。
3. **Rust 优先**：正则、文件枚举、编码探测均在 Rust 侧实现，不 shell out 到 `rg` 等外部二进制
   （现有 `search.rs` 走 `Command::new("rg")` 是过渡态，最终须内置）。
4. **回归红线**：改 Grep/列块不得打红 `minimal-layout.spec.ts` 等既有 UAT。

| C-09 Esc 退出 | ✅ | 已有分支 + UAT |
| C-10 超宽内容处理 | ✅ | `columnPrompt` 补空格/截断保持对齐 |

额外修掉的既有缺陷（不属 Sakura 规格，但影响对标体验）：
- **Alt+拖动根本拖不出矩形** —— 原来只有 `mousedown` 设锚点，没有 `mousemove`/`mouseup`，
  只能点出 1×1 的块。已补 `window` 级拖动收尾，并把光标对齐到列块右下角。
- **列块区域绕过语法高亮** —— 原渲染直接 `escapeHtml(原文)`，列块内的代码失去配色。
  已改为在 token 流上按字符列切分（`splitHighlighted` / `splitAt`），只在 token 边界开口。
- **UTF-16 劈裂** —— `columnSelectedText` / `columnDelete` / `columnPrompt` 原用 `String.slice`，
  在 emoji 等代理对上会劈开半个字符。已全部改用 `charSlice`（按码点）。
- **坐标换算写死** —— `lineH = 18` / `chW = 7` / `gutter = 40` 硬编码，改字号或页面缩放即偏移。
  已改为从真实渲染测量（`posFromEvent`）。
- **插入后高亮误显示** —— `c1 || c0 + 1` 让塌缩态（插入点）画成"选中 1 字符"。已区分塌缩态画光标。

### 4.3 已知未达标项（诚实清单）

1. **后端仍 shell out 到 `rg`**（`search.rs:66` `Command::new("rg")`）。违反 §3 原则 3，
   Windows 上 rg 不一定在 PATH，缺了就退到 `search_fallback`（无 glob 支持）。
   彻底方案是把 ripgrep 的 glob/正则引擎内置进 `sakura-rs`。
2. **列块模式无可见指示**（C-08）—— 用户进列块后除高亮外看不出当前模式，与 Sakura 有差距。
3. **Grep 结果仍在对话框里** —— Sakura 是独立窗口，可在关闭对话框后继续用。
4. **无实时搜索**（G-73）—— Sakura 输入即出结果。
