# .NEMA 全语法变化矩阵 · 七列完整审查版

本版把每条语法拆成多个独立的变化案例，分别列出其预期渲染结果、错误行为和设计理由。不再把多个变化写法合并到一个单元格。

需要先明确一个边界：任意字符串、任意列数、任意节点数的具体组合是无限的，无法逐字枚举。因此这里采用等价类 + 边界值 + 错误注入 + 状态组合的方式覆盖所有主要语法分支。最终解释器还应通过自动生成测试验证这些组合。

## 一、Table 表格模式

### A. 领域头、表头、列数及首行所有变化

| 语法 | 说明 | 具体例子 | 设计理由 | 避免的异常 | 变化写法 | 变化渲染结果 |
| -- | -- | -- | -- | -- | -- | -- |
| ` \N REV` | Table 领域头 | ` \1 1` | 明确领域边界 | 普通数据误判为领域头 | ` \2 1` | 创建 Table #2，Rev 1 |
| 同上 | 修订号变化 | ` \1 1` | 保持修订可追踪 | 修改后失去版本关系 | ` \1 2` | 创建 Table #1，Rev 2 |
| 同上 | 大编号 | ` \1 1` | 支持多个领域 | 编号空间不足 | ` \999 10` | Table #999，Rev 10 |

| 同上 | 非法前导零 | ` \1 1` | 唯一编码形式 | `01` 与 `1` 同义 | ` \01 1` | 错误：非规范 ID |
| 同上 | 非法多空格 | ` \1 1` | 严格空格规则 | 解释器自动折叠空格 | `  \1 1` | 错误：领域头前置空格数异常 |
| `\#` | 显式表头 | `\# Name Status` | 彻底区分表头和数据 | 首列为空时误识别表头 | `\# Name Status Detail` | 创建三列命名表格 |
| 同上 | 单列表头 | `\# Name Status` | 支持最小表格 | 强制要求至少两列 | `\# Name` | 创建单列表格 |
| 同上 | 表头包含空格 | `\# Name Status` | 保留真实名称 | 列名被拆分 | `\# Full\ Name Status` | 两列：Full Name、Status |
| 同上 | 空表头字段 | `\# Name Status` | 保证字段可寻址 | 空键导致访问歧义 | `\# Name \e` | 错误：空列名 |
| 同上 | 重复列名 | `\# Name Status` | 列名唯一 | JSON 转换出现重复键 | `\# Name Name` | 错误：列名重复 |
| 同上 | 缺少列名 | `\# Name Status` | 保证 Schema 完整 | 建立零列命名表格 | `\#` | 错误：没有列名 |
| 同上 | 数据后再声明表头 | `\# Name Status` | 结构固定 | 中途重定义数据意义 | 数据之后出现 `\# Name Status` | 错误：表头位置非法 |
| 无 `\#` | 自动列名 | `Claude Ready` | 减少额外表头 Token | AI 自行推断列名 | `A B C` | column1～column3 |

| 同上 | 首列空字符串 | `A B` | 保留空文本 | 空文本被误当 Null | `\e Ready` | column1=""，column2=Ready |
| 同上 | 首列缺失 | `A B` | 保留 Missing 状态 | 将未提供当作 Null | `\_ Ready` | column1=Missing，column2=Ready |
| 同上 | 首列无值，第三列有值 | `A B C` | 保持精确列坐标 | 非空字段向左移动 | `\_ \_ Active` | X0、X1 Missing；X2=Active |
| 同上 | 首行全部 Null | `A B C` | 允许全空值记录 | 无法推断列数 | `~ ~ ~` | 三列，全部 Null |
| 同上 | 首行全部 Missing | `A B C` | 支持全缺失记录 | 误当空行而跳过 | `\_ \_ \_` | 三列，全部 Missing |
| `\%N` | 候选显式列宽 | `\%3` | 无需实际数据也可定义结构 | 纯空表格无法知道列数 | `\%5` | 建立五列 Schema |
| 同上 | 单列声明 | `\%3` | 支持一列表格 | 零列与一列混淆 | `\%1` | 一列表格 |

| `X0 X1` | 正常记录 | `Claude Ready` | 最简数据表示 | 不必要的键重复 | `Codex Running` | X0=Codex；X1=Running |
| 同上 | 三字段记录 | `A B` | 支持多列 | 字段数量不固定 | `A B C` | X0=A；X1=B；X2=C |

| 同上 | 中间 Null | `A ~ C` | 保留中间位置 | 后续列错位 | `A ~ C D` | X1=null，其他位置不变 |
| 同上 | 末列 Null | `A ~` | 区分末列 Null 与缺失 | 转换时丢失状态 | `A B ~` | X2=null |
| `\e` | 第一列空字符串 | `A \e` | 保留真实空文本 | 空串被当成 Null | `\e Ready` | X0="" |

| `\_` | 第一列 Missing | `A B` | 区分未提供 | Patch 意外清空字段 | `\_ Ready` | X0=Missing |
| 同上 | 中间 Missing | `A B C` | 保留稀疏结构 | 后续列左移 | `A \_ C` | X1=Missing |
| 同上 | 末列 Missing | `A B C` | 允许部分记录 | 强迫填写无意义值 | `A B \_` | X2=Missing |
| 尾列省略 | 在已知列宽下允许省略尾列 | `A B C` | 减少 Token | 将缺失误当 Null | `A B` | X2=Missing |
| 同上 | 仅第一列存在 | `A B C` | 支持部分更新 | 缺失被当空字符串 | `A` | X1、X2 Missing |
| `\~` | 字面 `~` | `A ~` | 区分数据与特殊值 | 普通内容被清空 | `A \~` | X1="\~" |
| `\ ` | 字段内空格 | `Hello\ World Ready` | 保留词组 | 自然语言被拆列 | `New\ York Active` | X0="New York" |
| 连续分隔空格 | 字段之间两个空格 | `A B` | 强制规范字段切分 | 不同解析器折叠方式不同 | `A  B` | 错误：重复分隔空格 |
| 末尾多余空格 | 记录后有一个空格 | `A B` | 禁止隐式空列 | 意外产生空字段 | `A B ` | 错误：尾随分隔空格 |
| ` X1` | 续写第二列 | ` Retrying` | 局部追加 | 重复整行内容 | ` RetryLater` | 上一记录 X1 追加 RetryLater |
| `  X2` | 续写第三列 | `  HTTP401` | 精确指定扩展列 | 错误覆盖其他列 | `  Timeout` | 上一记录 X2 追加 Timeout |
| `   X3` | 续写第四列 | `   RetryOnce` | 支持更高列号 | 属性错位 | `   Review` | 上一记录 X3 追加 Review |
| 续写第一条之前 | 无目标记录 | ` Retrying` | 禁止孤立追加 | 错误创建隐式记录 | 领域头后直接 ` Retrying` | 错误：无续写目标 |
| 续写 Null | 目标字段为 Null | `~ Ready` | Null 不应被偷偷转为文本 | 状态被静默改变 | 先 `A ~`，后 ` Retrying` | 错误：不能直接续写 Null |
| 续写 Missing | 目标字段缺失 | `A \_` | Missing 不隐式创建字段 | Patch 意外填充 | 先 `A \_`，后 ` Retrying` | 错误：不能直接续写 Missing |
| 续写空字符串 | 目标字段为 `""` | `A \e` | 空文本可以明确追加 | Null 与空串混同 | 先 `A \e`，后 ` Retrying` | X1="Retrying" |
| 超出列宽续写 | 对不存在的 X3 追加 | 两列表格 | 保持 Schema 固定 | 续写隐式扩列 | 两列表格中写 `   Retry` | 错误：列坐标越界 |

Table 的关键设计结论：行首空格不再承担表头识别，只承担列定位。显式表头必须使用独立标记；所有空位状态必须区分。这避免了你发现的“第一行第一列为空”问题。

| 续写 Null | 目标为 Null | `A ~ C` | 避免状态隐式转换 | Null 自动变文本 | 随后 ` ReduceRisk` | 错误：不能直接追加到 Null |
| 续写 Missing | 目标为 Missing | `A \_ C` | 避免覆盖未提供语义 | 隐式修改原始数据 | 随后 ` ReduceRisk` | 错误：不能直接追加到 Missing |
| 续写空字符串 | 目标为 `""` | `A \e C` | 空文本可以扩展 | 空串与 Null 混淆 | 随后 ` ReduceRisk` | Why="ReduceRisk" |
| X0 追加 | 现有空格坐标规则缺少 X0 续写形式 | `BuildLogin` | 暴露规范缺口 | 顶格续写被误建为新任务 | 顶格 `MoreDetails` | 当前只能解释为新记录，不能当作 X0 追加 |

现有规则中，顶格行用于创建新记录，一个空格指向 X1，因此没有可直接表示“追加上一条记录的 What”的行首空格数量。

| 字节无损 | 末尾无 LF | `A B` | 支持真实文件字节一致 | 解压器自动加换行 | 源文件直接 EOF | 解码必须仍是无末尾 LF |

| 字节无损 | 连续空行 | 多个 LF | 保留源文件字节 | 空行被规范化删除 | 两条记录间有三个 LF | 恢复完全相同的 LF 数量 |
| 字节无损 | 字面反斜杠 | `C:\\Tools` | 保留转义原文 | 解压器重复解码 | 原始编码含 `\\` | 恢复原始编码字节，不是只恢复 AST |
| 字节无损 | 字面 `^0` | 普通文本 | 防止字典误替换 | 用户数据损坏 | 原文件内容含 `^0` | 解码后保持字面 `^0` |
| 字节无损 | 源文件含特殊行 | ` \?2 1` | 保留领域头原字节 | 控制字符被规范化 | 文件含多个领域头 | 所有领域头逐字节恢复 |
| 哈希校验 | 编解码前后核对 | SHA-256 | 验证实际无损 | 语义相同但字节不同 | 原文件与还原文件比较 | 哈希必须相等 |
| 语义往返 | AST 再编码 | AST → `.nema` | 保证结构可交换 | 语义字段丢失 | Parse → Serialize → Parse | 两个 AST 语义相等 |

| Token 基准 | 紧凑 JSON | 同一 AST | 检查相对效率 | 数据字段不等价 | 紧凑 JSON 序列化 | 输出真实 Token |
| Token 基准 | 紧凑 YAML | 同一 AST | 对照目标格式 | 故意使用冗余 YAML | 等价紧凑 YAML | 输出真实 Token |
| 端到端成本 | 加入解析说明 | 格式 + 解码协议 | 比较真实模型成本 | 漏掉说明文本开销 | 连同解码指令一起发送 | 输出完整 Token 成本 |
| 多 tokenizer | 使用不同模型分词器 | GPT / Claude 等 | 避免针对单模型过拟合 | 本地 BPE 数据冒充 API 计费 | 同样样品分别计数 | 每个模型独立报告 |
| 压缩选择 | 在候选中选低成本形式 | 原生、字典、组合 | 最小化实际 Token | 压缩算法反而增加消耗 | 比较所有候选总成本 | 选最低成本且可逆的格式 |

## 六、全局词法、文件、版本及多 Agent 协作

### A. 空格、换行、领域边界与文件结构

| 语法 | 说明 | 具体例子 | 设计理由 | 避免的异常 | 变化写法 | 变化渲染结果 |
| -- | -- | -- | -- | -- | -- | -- |
| `U+0020` | 单个半角空格分隔字段 | `A B` | 统一语法空白 | 不同空白字符混用 | `A B C` | 三个字段 |
| 同上 | N 个前导空格 | `  HTTP401` | 以空格定位列 | 依赖 Tab 宽度 | 三个前导空格加 `Retry` | 根据模式定位相应列 |
| 同上 | 两个连续分隔空格 | `A B` | 不静默折叠字段 | 空字段推断不一致 | `A  B` | 错误：重复分隔符 |
| 同上 | 尾随空格 | `A B` | 避免隐藏字符 | 编辑器自动 trim 改变语义 | `A B ` | 错误：多余尾随空格 |
| `U+0009` | 原始 Tab 禁止用于语法 | `A B` | 不依赖不同制表宽度 | 空格与 Tab 混淆 | 用 Tab 分隔 A、B | 错误：非法语法空白 |
| `U+3000` | 全角空格禁止用于语法 | `A B` | 字节与视觉一致 | 全角空格看起来像缩进 | 用全角空格分隔 | 错误：非法语法空白 |
| `LF` | 物理换行 | 第一行后 LF | 统一记录切分 | 平台换行行为不同 | A + LF + B | 两条物理行 |
| `CRLF` | 非规范物理换行 | LF | 防止隐式变更文件字节 | Windows 自动转行 | A + CRLF + B | 严格模式报错，显式迁移可转换 |
| `EOF` | 文件直接结束 | `A B` | 不强制尾部冗余换行 | 额外 Token 开销 | 最后一行无 LF | 正常结束 |
| 同上 | 文件末尾一个 LF | `A B` | 容许通常编辑器保存形式 | 无末尾 LF 被当成另一个语义 | 最后有一个 LF | 正常结束，字节与无 LF 不同 |
| 空行 | 纯空物理行 | 两记录间空行 | 美观分段而不修改 AST | 空行被当作空记录 | 连续三个空行 | 不新增业务记录 |
| 同上 | 文件只含空行 | 正常文件 | 明确无领域状态 | 默认生成虚假表格 | 仅多个 LF | 建议错误：缺少领域 |
| 领域头匹配 | 仅完整行识别 | ` \1 1` | 消除前缀误识别 | 普通正文误触发领域 | ` \1 1 Extra` | 错误：非法领域头 |
| 同上 | 非法第二个空格 | ` \1 1` | 控制字段严格分隔 | 不同实现自动纠正 | ` \1  1` | 错误：多余分隔空格 |
| 同上 | 非法修订号 | ` \1 1` | 修订号可比较 | 不可解析版本 | ` \1 X` | 错误：非法 REV |
| 同上 | 缺少修订号 | ` \1 1` | 明确领域版本 | 默认值不一致 | ` \1` | 错误：REV 缺失 |
| 领域重复 | 同模式同编号 | ` \1 1` | 防止对象覆盖 | 两个领域合并错误 | 再次出现 ` \1 1` | 默认报重复领域 |
| 跨模式同编号 | 不同模式均使用 #1 | ` \1 1` | 明确命名空间 | ID 唯一范围不一致 | ` \?1 1` | 候选：允许，按模式 + ID 区分 |
| 同领域不同修订 | 相同 ID，不同 REV | ` \1 1` | 支持版本追踪 | 同一文件多个当前版本 | 再出现 ` \1 2` | 待定：允许版本快照或禁止重复身份 |
| 模式切换 | 不同领域相邻出现 | ` \?2 1` | 支持混合结构 | 上一个模式状态泄漏 | Table 后直接 Graph 领域头 | 切换解析状态 |
| 空领域 | 领域头后无正文 | ` \1 1` | 支持结构占位 | 自动创建虚假记录 | 领域头后直接 EOF | 建议允许零记录领域 |
| 续写越领域 | 切换领域后出现续写 | ` Retrying` | 领域内部封闭 | 内容进入旧领域 | Graph 领域头后直接 ` Retrying` | 错误：没有当前目标 |

## 七、跨语法组合必须进一步覆盖的情况

| 组合情况 | 变化写法 | 预期结果或异常 |
| -- | -- | -- |
| 无表头 Table + 首列 Missing | `\_ Ready` | 自动建立两列；X0 Missing |
| 显式表头 + 首列 Null | `\# Name Status` 后写 `~ Ready` | Name=null |
| 显式表头 + 首列空字符串 | `\# Name Status` 后写 `\e Ready` | Name="" |
| 显式表头 + 首列 Missing | `\# Name Status` 后写 `\_ Ready` | Name=Missing |
| 显式列宽 + 全列 Missing | `\%3` 后写 `\_ \_ \_` | 三列全部 Missing |
| 自动表头 + 后续更宽记录 | `A B` 后写 `C D E` | 列宽冲突错误 |
| Null + 纵向续写 | `A ~` 后写 ` Retrying` | 状态转换错误 |
| Missing + 纵向续写 | `A \_` 后写 ` Retrying` | 状态转换错误 |
| 空字符串 + 纵向续写 | `A \e` 后写 ` Retrying` | X1="Retrying" |
| 5W1H + 仅 X5 有值 | `\_ \_ \_ \_ \_ API` | Where=API |
| 5W1H + 首字段为 `?` | `? Why How` | What="?"，不是领域头 |
| 5W1H + 多个逻辑换行 | `What\ line1\nline2` | 同一字段含换行 |
| Graph + 节点名含 `>` | `A Login\>API` | Node 名称为 Login>API |
| Graph + 非法边表达式 | `A>X` | 错误，不降级为 Node |
| Graph + 平行边 | `A>X>B`、`A>Y>B` | 两条不同身份的关系 |
| Graph + 前向引用 | 先 `A>X>B`，后定义 A、B | 最终校验通过 |
| Graph + 删除被引用节点 | Edge 仍存在，Node B 被删除 | 悬空关系错误 |
| 跨领域 + 相同 Node ID | 两个 Graph 都定义 A | 按领域隔离 |
| 字典 + 字面 `^0` | 原文存在 `^0` | 解码后仍为字面 `^0` |
| 字典 + 字段内逻辑 LF | 数据含 `\n` | 传输后字节及字段语义均保持 |
| 字典 + 域头反斜杠 | 原文含 ` \?1 1` | 还原完全相同的领域头字节 |
| 字典 + 无压缩收益 | 词组重复次数不足 | 不启用字典 |
| `.nema` + JSON | 相同 AST | 信息完整度一致 |
| `.nema` + YAML | 相同 AST | 结构和空值状态一致 |
| `.nemat` + 原始 `.nema` | Encode → Decode | 字节级完全一致 |
| 多 Agent + 同一 Node 修改 | Agent A、B 改同一个属性 | 冲突 |
| 多 Agent + 不同 Node 修改 | Agent A 改 Node A，B 改 Node B | 无其他冲突时可合并 |

## 八、穷举自动测试的设计与 64 态组合验证器

固定三列表格，每列有四种基本状态：
- Value：普通值
- Null：`~`
- Empty：`\e`
- Missing：`\_`

仅这三个字段的基本状态组合就有 \(4^3 = 64\) 种。
例如：
X0=Value, X1=Missing, X2=Null
变化写法：
```nema
 \1 1
\# column1 column2 column3
A \_ ~


```
变化渲染结果：
| column1 | column2 | column3 |
| --- | --- | --- |
| A | Missing | null |
