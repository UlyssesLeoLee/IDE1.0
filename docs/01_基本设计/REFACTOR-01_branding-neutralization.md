## 1. 背景と目的

本プロジェクトは初期フェーズで、ある**既存のオープンソース Win32 テキストエディタ**
(以降「参照実装」と呼ぶ) の機能・挙動・鍵割当を対標として開発してきた。
その結果、その名称が以下の箇所に大量に混入していた。

| 層 | 該当箇所 | 例 |
|---|---|---|
| crate 名 | ディレクトリ・Cargo.toml | `crates/sakura-rs`, `name = "sakura-rs"` |
| コード識別子 | Rust / JavaScript | `sakura_rs::`, `sakuraMove`, `sakuraKey` |
| ファイル名 | テスト・仕様書 | `sakura_parity.rs`, `grep-sakura.spec.ts` |
| 散文 | ドキュメント 22 份 | 「〜 風」「対標 〜」 |

**リスク:** 配布物・選考資料に他社名称が大量混入すると、
「既存エディタを流用した」「偽装」と誤解される恐れがある。
ライセンスの主張と事実が乖離し、無用な法務紛争につながる恐れがある。

**目的:** ブランドを中立名称に統一し、参照実装を **模倣対象ではなく「参考資料」** として位置づける。

---

## 2. 命名方針

| 対象 | 方針 | 決定 |
|---|---|---|
| crate 名 | 職責を示す中立名 | **`editcore`** |
| コード識別子 | 挙動を表す中立名 | `legacyMove` / `editorKey` |
| ファイル名 | 機能を表す中立名 | `editor_parity.rs` / `grep.spec.ts` |
| 散文 | 「参考実装」「従来エディタ風」等 | — |
| **上流 URL** | **維持** | 事実的引用 |
| **上流ソースディレクトリ名** | **維持** | `sakura_core/...` は実在ファイルを指す |
| **ディスク上のディレクトリ名** | **保留 (別判断)** | §5 参照 |

### 2.1 URL を消さない理由

参照実装の URL・ソースパスは**事実的引用**であり、削除すると次の問題が発生する:

1. **出所の追跡不能** — 鍵割当表 (`CKeyBind.cpp`) や仕様書 (`HLP*.html`) を
   実際に参照した事実は消える
2. **意図的な隠蔽と見なされる** — 参照したのに痕跡を消すと、逆に
   「把握したのに伏せた」= より悪印象
3. **ライセンス整合性の検証不能** — 参照実装のライセンス (zlib 系) との
   互換性を後から検証できなくなる

商標上の利用と出所の明示は両立可能であり、両立、かつ正しい対応。

## 5. 未実施項目 (要判断)

| 項目 | 内容 |
|---|---|
| 対象 | `.sakura-backup` (自動バックアップ先) / `.sakura-cursor` (カーソル位置保存先) |
