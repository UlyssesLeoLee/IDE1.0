| 属性 | 值 |

## 1. 系统测试目的

从最终使用者视角证明“普通文本不受影响、Markdown编辑更好用、文档无损、插件可扩展且不会拖慢IDE”。系统测试不以底层单元Mock通过为替代。

## 2. 测试类型

- 功能端到端：普通文本→工具栏→命令→保存→重开；Mermaid与多入口一致性。
- 非功能：启动增量、内存、1MiB输入、冷开预览、10/50MiB降级、关闭资源释放。
- 安全：脚本注入、远程资源外发、插件越权、AI外发授权。
- 兼容：Windows 10/11（实际支持版另确认）、DPI100/150/200、暗亮主题、中日IME、UTF-8 BOM/Shift-JIS/CRLF。
- 可靠性：外部修改并发、worker崩溃、预览不可用、磁盘保存失败。

## 4. 性能测量协议（不得凭感觉得出通过）

| 量化项目 | 指标 | 统计方法 |
|---|---|---|
| 普通TXT冷启动额外耗时 | P95 ≤ 100 ms | 裸宿主/插件版同机，各≥30轮，扣除基线 |
| 非MD常驻内存增量 | 目标 ≤ 10 MiB | 记录主进程与子进程稳态增量 |
| 1 MiB MD 文本可编辑时间 | P95 ≤ 1 s | ≥30轮，热/冷分开 |
| 1 MiB MD 可见按键延迟 | P95 ≤ 50 ms | 多个输入位置≥500次，事件到绘制 |
| 1 MiB MD 首次基础预览 | P95 ≤ 2 s | ≥30轮，明确Runtime预热状态 |
| 大文件降级 | 仍能原生源码编辑/保存 | 10/50MiB，记录策略触发与缺陷 |

- P95采用升序排序的 nearest-rank 定义，即 rank=ceil(0.95×样本数)；必要时可按项目批准的统计方案统一调整，不能混用。
- 测量中锁定CPU电源计划、杀毒扫描状态、磁盘与网络背景负载，保存原始CSV数据。
- 性能目标是需求草案阈值，应于Stage 0完成基线评审；改变阈值需要CR并更新NFR/测试。

## 5. 环境矩阵

| 维度 | 必测 | 说明 |
|---|---|---|
| OS | Windows 10/11 中项目声明支持的版本 | 具体build以实际支持清单为准 |

| 文档大小 | <1KiB / 1MiB / 10MiB / 50MiB | 大文由fixtures脚本现场生成 |
| 编码 | UTF8、UTF8 BOM、Shift-JIS | 以及换行LF/CRLF/MIXED |
| 模式 | 纯TXT、MD源码、MD分屏、即时渲染(P1) | P2只独立启用测试 |
| 插件 | 0、1、100份Manifest、崩溃插件 | 验证启动与释放 |
| 网络 | 断网/受限授权网络 | 预览默认不得外发 |

## 6. 主要系统异常验收

- 任意插件worker崩溃，原生编辑/保存继续工作。
- 任意图表渲染失败，用户的Mermaid原文不丢失。
- 文件外部更改，绝不可静默覆盖。
- 没有WebView2（或同等预览组件）时，源码可编辑。
- 低内存/大文件场景安全自动或提示降级。
- 未知语法在显示模式切换时不被删除或自动整理。

## 7. 缺陷优先级与判退标准

| 等级 | 判定例 | 发布门禁 |
|---|---|---|
| S1致命 | 数据丢失、未授权外传、宿主保存失效 | 任何开放项一票否决 |
| S2严重 | 关键编辑事务非原子、输入法不可用、P0主要流程不可用 | P0发布不得遗留 |
| S3一般 | 特定图形预览差异、提示不全、局部UI瑕疵 | 需明确风险承接 |
| S4轻微 | 非关键布局偏差或文案问题 | 登记下版本修复 |

## 8. 系统测试退出与验收

- 纳入迭代的P0功能用例执行率100%，通过率100%。
- 所有P0适用NFR必须有实测/检查证据，阈值未批准或无实测不可判Pass。
- 数据丢失、越权访问与宿主稳定性用例全部通过。
- S1/S2无开放缺陷，S3有批准的剩余风险说明。
- P1/P2未交付可标记N/A且不阻断P0（除共同安全/保真约束）。
