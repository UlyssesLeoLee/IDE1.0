## 1. UT目的

隔离验证宿主适配、命令事务、文本保真、结构解析、工具状态、资源操作、渲染调度、插件Manifest及权限判定等细节。不依赖真实Git或AI服务，测试均可由 FakeHost/MockClock/MockPermission 提供可重复输入。

## 2. 测试对象与隔离策略

| 单元 | UT验证要点 | Mock边界 |
|---|---|---|
| PositionCodec | UTF8/UTF16/Shift-JIS、CRLF、Emoji、组合字符offset往返 | FakeHost只返回坐标语义 |
| CommandBus | 版本检查、范围合法、原子事务、UndoID、拒绝副作用 | Mock `applyAtomic` |
| MarkdownIndex | Heading识别、围栏内标题抑制、sourceRange、增量版本 | FakeParserPort |
| ToolContext | 选区/代码围栏/IME/只读状态下命令可用性 | FakeSelection/IME |
| Slash | 触发语境、候选、Esc保留源文本 | Mock keystroke stream |
| Table/Asset | 转义管道、相对路径、安全资源写入/回滚 | VirtualFS |
| PreviewManager | 惰性装载、版本取消、销毁资源 | FakePreviewPort |
| PluginRegistry | schema/命令重复/授权/worker崩溃 | FakeWorker, FakePermissionHost |
| AI/Trace/Export | 范围受限提案、工作树隔离、无副作用导出 | Mock下游端口 |

## 3. 共通执行步骤

1. 建立每例独立 `FakeDocument(version=1)` 与可观察的状态快照。
2. 根据 `fixtures/` 和用例数据列注入文本、位置、权限、预期版本。
3. 执行目标公开函数/命令，不直接调用私有状态改写生产逻辑。
4. 断言返回值、Buffer内容、EditTransaction日志、Undo粒度、事件与资源引用计数。
5. 在异常场景断言**无部分变更**、无不应触发的文件或网络操作。

## 5. 单体完成基准（建议）

- 所有纳入迭代的P0单测执行率100%，通过率100%；P1/P2若未实现标记Not Applicable，不得记录Pass。
- CommandBus、PositionCodec、插件Schema/Permission、预览安全净化、数据保真路径的关键分支需要覆盖正常/异常/边界；项目可将关键模块分支覆盖率目标设为≥90%，需真实采集报告。
- 禁止以模拟器的断言代替真实宿主原子撤销行为，该项还须IT验证。
- 每个失败保留输入版本、日志、断言diff及缺陷ID。

## 6. UT必要测试替身契约

FakeHost要支持模拟`expectedVersion`冲突、IME composing、只读、Undo失败、保存前外部变化；FakeWorker要支持崩溃、延迟、超大消息、恶意越权请求；FakeRenderer要支持旧版本结果迟到、卸载与渲染失败。
